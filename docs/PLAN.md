# AI Leader ID — план проекта

Версия 3 от 27 сентября 2026 — по состоянию `main` · тех-лид: Мейірбек

## Суть

Регистрация, анкета, тест, статусы и решения комиссии у inVision U уже есть. Мы строим отдельный **AI-слой вокруг интервью**. Он принимает данные по JSON API и возвращает объяснимые материалы для интервьюера и комиссии. Решение всегда принимает человек: в API нет `accept/reject`.

Главное отличие от команд с AI-интервью — **симулятор**. AI-интервью подменяет человека и решает без доказательств. Симулятор создаёт рабочую ситуацию, в которой кандидат *показывает* лидерство, а человек получает доказательства с цитатами.

**Главное правило объёма.** Мы не доделываем все модули одинаково полно: это дало бы пять полуфункций вместо одного убедительного продукта. **M2 → M3 — цельный, доказуемый продукт.** M1, M4, M5, сверка C и шаги кандидата S, P, V — тонкие, но настоящие.

## Минимальный путь питча

Выбор синтетического кандидата → бриф M1 со сверкой «до» → симуляция M2 → отчёт M3 с дословными цитатами → интервью: M4 заблокирован до слепых баллов интервьюера → сверка «после» → M5 показывает качество вопросов и калибровку.

Этот путь обязан работать **офлайн через replay** записанных ответов. Если голос или сеть откажут на сцене, демо остаётся целым. В `replay` симуляция A, B и C показывается из записи («Завершить симуляцию … из записи»): живой разговор — это новые реплики, для которых записанных ответов нет.

## 2. Рубрика D.R.I.V.E.

| Код | Компетенция | Что ищем в доказательствах | Как видно в симуляторе |
|---|---|---|---|
| **D** | Disciplined Resilience | реакция на неудачу, восстановление, последовательность действий | после срыва плана выстраивает шаги восстановления |
| **R** | Responsible Innovation | инициатива с оценкой рисков, последствий и ответственности | предлагает новое решение и сам называет, что может пойти не так |
| **I** | Insightful Vision | понимание контекста, долгосрочное мышление, ясная цель | видит, что стоит за конфликтом, держит общую цель |
| **V** | Values-Driven Leadership | решения на основе ценностей, уважение к людям, этические границы | в дилемме выбирает честность и уважительно объясняет почему |
| **E** | Entrepreneurial Execution | идея → действия, приоритизация, ответственность за результат | раскладывает кризис на шаги с владельцами и сроками |

Для каждой компетенции в `config/rubric.drive.json`:
- шкала `0–4` и `null` при недостатке данных;
- допустимые поведенческие индикаторы;
- запрещённые выводы;
- примеры валидных доказательств;
- шаблоны вопросов для интервью.

Ошибки английского на D.R.I.V.E. не влияют: English metrics идут отдельным блоком. Каждый сценарий симулятора даёт место проявить все пять компетенций.

## 3. Архитектура

```
браузер ──▶ web (Next.js, BFF /api/v1/*) ──X-API-Key──▶ api (NestJS) ──X-Internal-Token──▶ ml (FastAPI) ──▶ OpenAI · Deepgram
платформа inVision ──────────X-API-Key──────────▶      X-API-Key, роли, аудит          gateway: replay / record / live,
                                                        Idempotency-Key                 кэш, проверка схем и цитат,
                                                        toLLMView, удаление PII         лог стоимости, лимит бюджета
                                                        хранение, удаление видео
                                                        PostgreSQL
браузер ◀──── видеозвонок ────▶ LiveKit ◀── api выдаёт только токены комнат
```

**FastAPI — не универсальная AI-платформа**, а набор внутренних эндпоинтов под наши модули: `scenarios`, `simulation/turn`, `simulation/assessment`, `brief`, `transcribe`, `speech`, `consistency`, `surprise-question`, `interview/draft`, `quality-check`, `usage` и `health`. Полный список — `docs/contracts/ml.md`.

### Граница данных

NestJS хранит персональные данные и отправляет в ML только результат `toLLMView()`:

- технический `candidate_id`;
- содержательные ответы анкеты и теста;
- транскрипт симуляции;
- расшифровки сюрпризного ответа, презентации и интервью;
- заметки интервью и оценки интервьюера (только для калибровки M5, псевдонимно);
- разрешённые метаданные сценария.

Удаляются ФИО, ИИН, email, телефон, фото, пол, регион, школа, доход семьи и любые другие идентифицирующие поля.

Вторая граница — в ML. Во входных Pydantic-схемах таких полей нет, а лишние поля запрещены (`extra="forbid"`), так что поле с персональными данными не пройдёт валидацию.

Видео не уходит ни в одну модель: API вырезает звук (`ffmpeg`), ML его расшифровывает, звук удаляется. В LiveKit не уходит ничего личного: комната `slot-<id>`, участники `candidate` и `interviewer`.

### Каждый вывод AI — с проверенным доказательством

```json
{
  "claim": "Candidate described a concrete recovery plan after failure.",
  "evidence": [
    {
      "source": "simulation_turn",
      "sourceId": "turn_04",
      "quote": "I spoke with the team, changed the timeline and assigned owners."
    }
  ]
}
```

Модель способна выдать красивый балл с несуществующей цитатой, а это убивает главный принцип. Поэтому **после каждого ответа модели код проверяет каждую цитату**:

1. Цитата ищется в указанном источнике (`sourceId`) дословно — с точностью до пробелов и регистра кавычек.
2. Цитата не найдена — это доказательство выбрасывается, а событие пишется в лог.
3. У балла не осталось ни одного валидного доказательства — балл становится `null`.
4. Если выброшено больше половины доказательств ответа, запрос считается неудачным: один повтор, затем понятная ошибка.

Источники цитат: поле анкеты, пункт теста, ход симуляции, реплика интервью, заметка, сегмент сюрпризного ответа. Цитаты из презентации добавятся, когда ML примет `BriefRequest.presentation` (`docs/contracts/ml.md`, правило 6d); пока её расшифровка видна сотрудникам рядом с брифом.

**Серверное правило M4:** пока интервьюер не сохранил свои баллы, черновик нельзя ни сгенерировать, ни получить — оба запроса отвечают `409`. Так же закрыта сверка «после».

**Расшифровка интервью.** ИИ читает само интервью, а не пересказ интервьюера:
- **Два источника.** inVision присылает расшифровку своей записи, или экран интервьюера записывает звук — только с согласием кандидата. В видеозвонке V согласие кандидат даёт при входе; видео звонка не записывается.
- **Как расшифровывается.** Через шлюз (Deepgram, разделение по говорящим).
- **Что остаётся.** Аудио удаляется сразу после расшифровки. В модель уходит только текст, в репозиторий записи не попадают.
- **Зачем.** Черновик M4 цитирует реплики кандидата с таймкодом. M5 проверяет реальные вопросы интервьюера и долю его речи.

**Сюрпризный вопрос (S).** Видео-ответы на опубликованные вопросы можно отрепетировать; один неожиданный вопрос по собственной анкете показывает, как кандидат думает без подготовки.
- ML пишет вопрос по анкете при создании, а API раскрывает его только по `start` и ставит **серверный** дедлайн: 90 секунд и 15 секунд запаса. Повторный старт — `409 ALREADY_STARTED`, опоздание — `409 DEADLINE_PASSED`.
- Две отдельные галочки согласия: на видео и на обработку ответа. Без них — `400 CONSENT_REQUIRED`.
- Кандидат видит вопрос и свою запись до отправки, никакой оценки. Интервьюер и комиссия видят вопрос, расшифровку и плеер; `platform` получает `403` на видео.

**Видеопрезентация (P).** Удалённый этап отбора inVision начинается с видеопрезентации. Вопрос один для всех: *«In one to three minutes, in English: why inVision U, and one time you led other people — what you did, and what came of it.»* Запись в браузере или загрузка файла, от 1 до 3 минут и до 100 МБ, отправка одна.

**Видеоинтервью (V).** Интервьюер добавляет окна в недельном календаре, кандидат выбирает время в месячном. Правила держит сервер:
- вход открывается за 10 минут до начала;
- каждая сторона ждёт не больше 5 минут, иначе окно `missed`, и видно, кто не пришёл;
- после пропуска кандидат выбирает другой день (дни считаются в `INTERVIEW_TIME_ZONE`, по умолчанию Asia/Almaty);
- одна запись за раз, и никакой новой после состоявшегося интервью;
- интервью M4 создаётся, когда входит интервьюер; в звонке у него вопросы брифа, заметки и слепые баллы, без AI-черновика.

Без ключей LiveKit вход отвечает `503 VIDEO_UNAVAILABLE`, а окна и всё остальное работают.

**Follow-up в звонке (L, в работе).** Интервьюер нажимает «Listen to the answer», когда кандидат начинает отвечать, и «Suggest a follow-up», когда заканчивает. Записывается только дорожка кандидата, 3–120 секунд, с согласия на запись. ML возвращает 0–2 вопроса с причиной (`mismatch`, `vague`, `no_evidence`) и дословной цитатой. Каждое правило проверяется кодом: вопрос не наводящий, не о личном, не об английском и не о человеке. Ничего не идёт в черновик, сверку и баллы. Не realtime и никогда не слушает сам.

**Почему M5 так назван.** На трёх синтетических кандидатах честно доказать реальную предвзятость нельзя. M5 показывает сигналы качества вопросов и калибровки с рекомендациями — и не называет это «обнаружением дискриминации». Выводов о личности кандидата он не делает и его оценку не меняет.

inVision присылает снимок кандидата в теле запроса, поэтому синхронизировать базу заранее не нужно. Любой результат доступен и как JSON-файл той же схемы.

## 5. Симулятор — главный продукт

**Голосом, десять разных сюжетов, у каждого свой.** Кандидат говорит, а не печатает: вставить заготовленный ответ нельзя. Сценарий назначается случайно, поэтому ответы нельзя подсмотреть у знакомых.

```
голос кандидата ─▶ Deepgram: речь → текст ─▶ мини-ML: на какой тип ответа похоже ─▶ ветка сценария
                                                                                     │
      голос персонажа ◀─ Deepgram Aura ◀─ OpenAI: живая реплика персонажа для этой ветки ◀┘
```

- **Десять сюжетов** в `config/scenarios/<id>.json`, по сюжетам Бекнура из `docs/scenarios/`. Все построены по одной схеме:
  - 5–7 битов, 6–10 ходов кандидата, 6–8 минут;
  - бит описывает цель, какие компетенции D.R.I.V.E. он даёт проявить, **3–5 типов ответа** с примерами фраз и веткой для каждого, запасную ветку и лимит ходов;
  - **каждый сюжет даёт проявить все пять компетенций** — иначе баллы из разных сценариев нельзя сравнивать.
- **Стенд качества.** Сценарий получает `ready`, только когда судья оценил три эталонных прохождения из `fixtures/bench/<сценарий>/` (слабое, среднее, сильное) в пределах ±1 от ожидаемого, и все цитаты дословные. Запуск — `services/ml/scripts/quality_bench.py`, команда в `docs/DEPLOY.md`.
- **Пул на 27.09:** `ready` — `conflict-resolution`, `deadline-or-quality`, `public-mistake`. Остальные семь — `draft`: в прогоне 26.09 в пределах ±1 оказались 15 прохождений из 27, и у каждого из семи не прошло хотя бы одно. Их дорабатывают после питча. A, B и C закреплены за `conflict-resolution`, так что путь питча от пула не зависит.
- **Назначение:** случайно среди `ready`, сначала наименее использованные; одна симуляция на кандидата.
- **Мини-ML** — локальная модель эмбеддингов `all-MiniLM-L6-v2` в ML-сервисе, $0. Она сравнивает расшифрованный ответ с примерами фраз каждого типа ответа в текущем бите и выбирает ветку. Если сходство ниже порога, выбирается запасная ветка. Каждое решение — тип ответа, сходство, ветка — пишется в журнал: это объяснимость.
- **Мини-ML ведёт сюжет, но не ставит баллы.** Баллы ставит только судья M3 по всему транскрипту с цитатами. Любая ветка даёт проявить все компетенции, поэтому выбор ветки не наказывает.
- **Актёр** (OpenAI) пишет реплику персонажа для выбранной ветки — ≤ 60 слов, в образе. **Библия персонажа:** характер, цели, скрытый мотив, эмоциональное состояние (спокоен → защищается → сотрудничает).
- **Ограничения:** персонаж не оценивает, не подсказывает «правильный» ответ, не спрашивает о личном и о тяжёлом опыте. Уход от темы — мягкий возврат. Кандидат может остановиться в любой момент.
- **Голос:** «нажал — сказал — отпустил», до 60 секунд на ход. Субтитры всегда видны: кандидат видит, что распознано, и может перезаписать ход до отправки. Одновременно звучит только один голос.
- **Текстовый режим — только по заявке.** Сотрудник включает его для конкретного кандидата (нет микрофона, нарушение речи). Вставка текста заблокирована и там, а в отчёте видно, что симуляция шла текстом.
- **Справедливость к английскому:** судья читает смысл; акцент и темп на баллы не влияют. Низкая уверенность распознавания — флаг для человека, а не штраф.
- **Запись сессии:** транскрипт, биты, решения мини-ML и режиссёра; комиссия переходит от цитаты прямо к ходу.

**English metrics считаются кодом, $0:** слова в минуту по таймкодам речи, доля слов-паразитов, средняя длина реплики, лексическое разнообразие, ошибки через LanguageTool 6.6 (локально), оценка CEFR. Голосовой ввод делает все метрики доступными; именно их сверка сравнивает с заявленным уровнем.

## 11. Правила работы

- В `main` — только через PR; прямой пуш и force-push запрещены настройкой GitHub всем, включая владельца. Одобрить PR может только Мейірбек — он единственный в `.github/CODEOWNERS`. Свои PR он мерджит сам после зелёного CI.
- Одна ветка — один слайс одного человека. Маленькие коммиты с понятными сообщениями.
- Каждый меняет только свою часть репозитория (`CONTRIBUTING.md`, правило 3). Issue может перейти к другому человеку — тогда это написано в самом issue. Форма данных заморожена: её меняет только docs-PR Мейірбека и только добавлением.
- Код, идентификаторы и комментарии — на английском. Интерфейс кандидата — на английском, сотрудников — на английском или русском.
- Путь питча (`scripts/e2e/pitch-path.mjs`) должен оставаться зелёным в CI после каждого PR.

**Бюджет:**
- по умолчанию у всех `GATEWAY_MODE=replay`;
- живые вызовы — только по отдельным ключам проекта с лимитом на каждый ключ; ключи у Мейірбека, после питча они отзываются;
- лимит стоимости на один запрос в `models.json` и общий жёсткий `BUDGET_USD_CAP` в шлюзе;
- расход по записанным ответам — `python services/ml/scripts/budget_report.py`; итог — по страницам биллинга провайдеров.

**Публичный репозиторий:**
- ключи только в `.env`, в репозитории — `.env.example` без значений;
- включены GitHub secret scanning и push protection: пуш с ключом отклоняется ещё на сервере;
- в CI — отдельная проверка секретов (gitleaks);
- в репозиторий попадают только синтетические данные; записи голоса кандидатов — никогда. Синтетическое аудио в `fixtures/audio/` сгенерировано программой eSpeak NG.
