# AI Leader ID — план проекта

Версия от 21 сентября 2026 · тех-лид: Мейірбек

## Суть

Регистрация, анкета, тест, видео-интервью, статусы и решения комиссии у inVision U уже есть. Мы строим отдельный **AI-слой вокруг интервью** (M1–M5). Он принимает данные по JSON API и возвращает объяснимые материалы для интервьюера и комиссии. Решение всегда принимает человек: в API нет `accept/reject`.

Главное отличие от команд с AI-интервью — **симулятор (M2)**. AI-интервью подменяет человека и решает без доказательств. Симулятор создаёт рабочую ситуацию, в которой кандидат *показывает* лидерство, а человек получает доказательства с цитатами.

**Команда**

| Кто | Роль |
|---|---|
| Мейірбек | тех-лид и фронтенд |
| Наурызбек | бэкенд (NestJS) |
| Бекнур | ML (Python) |

**Сроки и ресурсы:** до питча ~10 дней, дни 4–7 — в поезде без интернета. Бюджет ~$20 на OpenAI, ключи у Мейірбека. Голос — Deepgram на кредит $200.

## 2. Рубрика D.R.I.V.E.

| Код | Компетенция | Что ищем в доказательствах | Как видно в симуляторе |
|---|---|---|---|
| **D** | Disciplined Resilience | реакция на неудачу, восстановление, последовательность действий | после срыва плана выстраивает шаги восстановления |
| **R** | Responsible Innovation | инициатива с оценкой рисков, последствий и ответственности | предлагает новое решение и сам называет, что может пойти не так |
| **I** | Insightful Vision | понимание контекста, долгосрочное мышление, ясная цель | видит, что стоит за конфликтом, держит общую цель |
| **V** | Values-Driven Leadership | решения на основе ценностей, уважение к людям, этические границы | в дилемме выбирает честность и уважительно объясняет почему |
| **E** | Entrepreneurial Execution | идея → действия, приоритизация, ответственность за результат | раскладывает кризис на шаги с владельцами и сроками |

Для каждой компетенции в `config/rubric.drive.json`:
- шкала `0–4` и `null` при недостатке данных;
- допустимые поведенческие индикаторы;
- запрещённые выводы;
- примеры валидных доказательств;
- шаблоны вопросов для интервью.

Ошибки английского на D.R.I.V.E. не влияют: English metrics идут отдельным блоком. Каждый сценарий симулятора даёт место проявить все пять компетенций.

## 3. Архитектура

```
inVision U / демо-стенд ──JSON API──▶ NestJS API ──внутренний API──▶ FastAPI ML ──▶ OpenAI · Deepgram
                                     auth, роли стенда                 ai/gateway: маршрутизация,
                                     валидация контрактов              кэш, проверка схем, лог
                                     toLLMView, удаление PII           токенов и стоимости,
                                     сессии, отчёты, аудит             лимит бюджета, M1–M5
                                     серверные правила доступа
```

### Граница данных

NestJS хранит персональные данные и отправляет в ML только результат `toLLMView()`:

- технический `candidate_id`;
- содержательные ответы анкеты и теста;
- транскрипт симуляции;
- заметки интервью и оценки интервьюера;
- разрешённые метаданные сценария.

Удаляются ФИО, ИИН, email, телефон, фото, пол, регион, школа, доход семьи и любые другие идентифицирующие поля.

Вторая граница — в ML. Во входных Pydantic-схемах таких полей нет, а лишние поля запрещены (`extra="forbid"`), так что поле с персональными данными не пройдёт валидацию.

### Каждый вывод AI — с доказательством

```json
{
  "claim": "Candidate described a concrete recovery plan after failure.",
  "evidence": [
    {
      "source": "simulation_turn",
      "sourceId": "turn_04",
      "quote": "I spoke with the team, changed the timeline and assigned owners."
    }
  ]
}
```

Если доказательства нет — `null`, а не низкий балл. Цитата обязана дословно совпадать с источником, это проверяется кодом.

## 4. Модули и API

| Модуль | Эндпоинты | Выход |
|---|---|---|
| **M1 Brief** | `POST /v1/briefs` (тело — `CandidateSnapshot`) · `GET /v1/briefs/:briefId` | вопросы по каждой букве D.R.I.V.E., флаги противоречий, темы для уточнения, отдельный English gap, evidence на каждую рекомендацию |
| **M2 Simulator** | `POST /v1/simulations` · `POST /v1/simulations/:id/turns` · `POST /v1/simulations/:id/complete` · `GET /v1/simulations/:id` | ход: `turnId`, транскрипт, реплика персонажа ≤ 60 слов с аудио, статус сценария; по завершении — полный транскрипт с id ходов |
| **M3 Judge** | `POST /v1/simulation-assessments` · `GET /v1/simulation-assessments/:id` · `GET /v1/simulation-assessments/:id/candidate-feedback` | комиссии: баллы `0–4 \| null` с `turnId`, уверенность, English metrics отдельно, вопросы для живого интервью. Кандидату: развивающий отзыв без баллов, ранжирования и намёков на решение |
| **M4 Draft** | `POST /v1/interviews/:id/interviewer-scores` · `POST /v1/interviews/:id/assessment-draft` · `GET /v1/interviews/:id/assessment-draft` | черновик, evidence из заметок, совпадения и расхождения с оценкой интервьюера, пункты для ручной проверки |
| **M5 Bias Guard** | `POST /v1/bias-checks/interview` · `POST /v1/bias-checks/calibration` · `GET /v1/bias-checks/:id` | наводящие и некорректные вопросы, неравное покрытие D.R.I.V.E., сдвиг шкалы интервьюера, рекомендации по калибровке |

**Серверное правило M4:** пока интервьюер не сохранил свои баллы, черновик нельзя ни сгенерировать, ни получить — оба запроса отвечают `409`.

M5 не делает выводов о личности кандидата и не меняет его оценку.

inVision присылает снимок кандидата в теле запроса, поэтому синхронизировать базу заранее не нужно. Любой результат доступен и как JSON-файл той же схемы.

## 5. Симулятор — главный козырь

- **Три сценария:** `config/scenarios/conflict-resolution.json`, `resource-crisis.json`, `ethical-dilemma.json`. В каждом 5–7 «битов», 6–10 ходов кандидата, 6–8 минут. Бит описывает цель, действие персонажа, какие компетенции D.R.I.V.E. он даёт проявить, условие выхода и запасной ход после N ходов.
- **Режиссёр и актёр — две роли модели.** Режиссёр (дешёвая модель, строгий JSON) решает переход между битами и логирует решение — это объяснимость. Актёр говорит в образе, ≤ 60 слов.
- **Библия персонажа:** характер, цели, скрытый мотив и эмоциональное состояние (спокоен → защищается → сотрудничает), которое меняется от поведения кандидата.
- **Ограничения:** персонаж не оценивает, не подсказывает «правильный» ответ, не спрашивает о личном и о тяжёлом опыте. Уход от темы — мягкий возврат. Кандидат может остановиться в любой момент.
- **Голос:** «нажал — сказал — отпустил». Deepgram распознаёт речь и озвучивает персонажа (Aura). Субтитры всегда видны, кандидат видит, что распознано. Цель задержки хода — меньше 3 секунд. Весь ход — один вызов ML-сервиса.
- **Текстовый режим** на том же конвейере — для работы офлайн и для доступности.
- **Справедливость к английскому:** судья читает текст, акцент и темп на оценку не влияют. Низкая уверенность распознавания — флаг, а не штраф.
- **Стенд качества:** для seed-кандидатов заранее написаны транскрипты и ожидаемые отчёты. Судья обязан воспроизвести ожидаемый рисунок баллов и цитировать дословно. Стенд прогоняется на каждое изменение промпта, офлайн — по записанным ответам.
- **Запись сессии:** транскрипт, биты и решения режиссёра; комиссия переходит от цитаты прямо к ходу.

**English metrics считаются кодом, $0:** слова в минуту по таймкодам, доля слов-паразитов, средняя длина реплики, лексическое разнообразие, ошибки через LanguageTool (локально), оценка CEFR.

## 6. Seed-кандидаты

| Кандидат | Цель демо |
|---|---|
| **A** | сильное execution, но недостаточно evidence по values |
| **B** | сильная vision, сложность с resilience |
| **C** | противоречивые ответы и явный `insufficient evidence` |

Для каждого кандидата готовим:
- обезличенную анкету и ответы теста;
- ожидаемый M1-бриф;
- транскрипт симуляции и ожидаемый M3-отчёт;
- заметки интервью, баллы интервьюера и сценарий M4;
- данные для M5;
- записанные ответы моделей для офлайна и `DEMO_MODE`.

## 7. Структура репозитория

```
apps/web/                 Next.js, English only                          (Мейірбек)
apps/api/src/
  modules/{briefs,simulations,simulation-assessments,interviews,bias-guard,candidates,audit}/
  ai-client/  privacy/to-llm-view.service.ts  config/                   (Наурызбек)
services/ml/app/
  gateway/  providers/  schemas/  cache/  metrics/english.py
  modules/{m1_brief,m2_simulator,m3_judge,m4_interview_draft,m5_bias_guard}.py   (Бекнур)
config/
  rubric.drive.json  models.json  scenarios/*.json
  prompts/{m1-brief,m2-director,m2-actor,m3-judge,m4-interview-draft,m5-bias-guard}.md
seed/                     кандидаты A/B/C и ожидаемые результаты
fixtures/cassettes/       записанные ответы моделей и Deepgram
docs/SPEC.md · README.md · CONTRIBUTING.md
```

`models.json` задаёт для каждой задачи провайдера, запасную модель, `max_tokens`, лимит стоимости, TTL кэша и запрет вызова в `DEMO_MODE`, если есть seed-результат.

**Переносим из черновика:** дизайн-систему (`apps/web/app/style.css`, `components/ui/*`, две темы, шрифты), каркас Next.js, MSW, генерацию клиента (`scripts/generate-api-client.mjs`, `packages/api-client`), экраны стенда (вход, анкета, тест на моках), каркас NestJS и Prisma, FastAPI-заготовку `services/ml`, английские тексты из `apps/web/messages/en.json`.

**Не переносим:** `next-intl` и смену языка, старые слайсы S0–S10, старый `openapi.yaml`.

## 11. Правила работы

- В `main` — только через PR с одним одобрением; прямой пуш запрещён настройкой GitHub. Свой PR никто не мерджит без одобрения другого участника: PR тех-лида одобряет Наурызбек или Бекнур.
- Одна ветка — один слайс одного человека. Маленькие коммиты с понятными сообщениями.
- Контракт слайса мерджится первым; фронтенд работает на MSW-моках из него.
- Код, идентификаторы, комментарии и интерфейс — на английском.
- Ключи только в `.env` у Мейірбека, в репозитории лежит `.env.example`.
- Шлюз пишет токены, стоимость и время каждого вызова и отказывает после `BUDGET_USD_CAP`.
- Только синтетические данные.

## 13. Definition of Done

Проект готов к питчу, когда:

- [ ] M1–M5 доступны через JSON API, все AI-ответы проходят проверку схемы.
- [ ] Каждый AI-вывод имеет evidence с дословной цитатой — или `null`.
- [ ] PII-тест подтверждает, что запрещённые поля не уходят в ML, а ML отклоняет запрос с таким полем.
- [ ] Английский не меняет баллы D.R.I.V.E. (тест: один транскрипт с ошибками и без — одинаковые баллы).
- [ ] M4 серверно заблокирован до оценок интервьюера — и генерация, и чтение (тест на `409`).
- [ ] Кандидат не видит баллы и намёки на решение.
- [ ] Демо проходит для A, B и C с `DEMO_MODE=true`, в том числе с выключенной сетью (`GATEWAY_MODE=replay`), за пять минут.
- [ ] Лог стоимости укладывается в $20.

**Как проверяем:**
- `docker compose up` поднимает web, api, ml и postgres.
- Скрипт прогоняет кандидатов A/B/C через M1–M5 и сравнивает ответы с ожидаемыми в `seed/`.
- Тесты NestJS (запрет M4, `toLLMView`) и FastAPI (схемы, PII, стенд качества, English metrics) зелёные в CI.
