# AI Leader ID — план проекта

Версия 2 от 21 сентября 2026 — с поправками по рискам · тех-лид: Мейірбек

## Суть

Регистрация, анкета, тест, видео-интервью, статусы и решения комиссии у inVision U уже есть. Мы строим отдельный **AI-слой вокруг интервью**. Он принимает данные по JSON API и возвращает объяснимые материалы для интервьюера и комиссии. Решение всегда принимает человек: в API нет `accept/reject`.

Главное отличие от команд с AI-интервью — **симулятор**. AI-интервью подменяет человека и решает без доказательств. Симулятор создаёт рабочую ситуацию, в которой кандидат *показывает* лидерство, а человек получает доказательства с цитатами.

**Главное правило объёма.** Мы не доделываем M1–M5 одинаково полно — за 10 дней это даст пять полуфункций вместо одного убедительного продукта. **M2 → M3 — цельный, доказуемый продукт.** M1, M4 и M5 — тонкие, но настоящие API-демонстрации.

**Команда**

| Кто | Роль |
|---|---|
| Мейірбек | тех-лид и фронтенд |
| Айбек | бэкенд (NestJS) |
| Наурызбек | ML (Python) |
| Бекнур | продукт-менеджер: презентация и питч |

**Сроки и ресурсы:** до питча ~10 дней. Бюджет ~$20 на OpenAI, ключи у Мейірбека. Голос — Deepgram на кредит $200.

## Минимальный путь питча

Выбор синтетического кандидата → бриф M1 → симуляция M2 голосом → отчёт M3 с дословными цитатами → M4 заблокирован до оценки интервьюера → M5 показывает качество вопросов.

Этот путь обязан работать **офлайн через replay** записанных ответов. Если голос или сеть откажут на сцене, демо остаётся целым.

| Объём | M2 и M3 — полностью; M1 и M4 — тонко; M5 — анализ качества вопросов и калибровки на seed-истории |

## 2. Рубрика D.R.I.V.E.

| Код | Компетенция | Что ищем в доказательствах | Как видно в симуляторе |
|---|---|---|---|
| **D** | Disciplined Resilience | реакция на неудачу, восстановление, последовательность действий | после срыва плана выстраивает шаги восстановления |
| **R** | Responsible Innovation | инициатива с оценкой рисков, последствий и ответственности | предлагает новое решение и сам называет, что может пойти не так |
| **I** | Insightful Vision | понимание контекста, долгосрочное мышление, ясная цель | видит, что стоит за конфликтом, держит общую цель |
| **V** | Values-Driven Leadership | решения на основе ценностей, уважение к людям, этические границы | в дилемме выбирает честность и уважительно объясняет почему |
| **E** | Entrepreneurial Execution | идея → действия, приоритизация, ответственность за результат | раскладывает кризис на шаги с владельцами и сроками |

Для каждой компетенции в `config/rubric.drive.json`:
- шкала `0–4` и `null` при недостатке данных;
- допустимые поведенческие индикаторы;
- запрещённые выводы;
- примеры валидных доказательств;
- шаблоны вопросов для интервью.

Ошибки английского на D.R.I.V.E. не влияют: English metrics идут отдельным блоком. Каждый сценарий симулятора даёт место проявить все пять компетенций.

## 3. Архитектура

```
inVision U / демо-стенд ──JSON API──▶ NestJS API ──внутренний API──▶ FastAPI ML ──▶ OpenAI · Deepgram
                                     X-API-Key, роли, аудит            gateway: маршрутизация,
                                     Idempotency-Key                   кэш, проверка схем,
                                     toLLMView, удаление PII           проверка цитат, лог
                                     сессии, отчёты                    стоимости, лимит бюджета
                                     серверные правила доступа
```

**FastAPI — не универсальная AI-платформа.** На старте у него три внутренних эндпоинта: ход симуляции, оценка симуляции, бриф. Черновик M4 и проверка качества M5 добавляются, когда до них дойдёт очередь.

### Граница данных

NestJS хранит персональные данные и отправляет в ML только результат `toLLMView()`:

- технический `candidate_id`;
- содержательные ответы анкеты и теста;
- транскрипт симуляции;
- заметки интервью и оценки интервьюера;
- разрешённые метаданные сценария.

Удаляются ФИО, ИИН, email, телефон, фото, пол, регион, школа, доход семьи и любые другие идентифицирующие поля.

Вторая граница — в ML. Во входных Pydantic-схемах таких полей нет, а лишние поля запрещены (`extra="forbid"`), так что поле с персональными данными не пройдёт валидацию.

### Каждый вывод AI — с проверенным доказательством

```json
{
  "claim": "Candidate described a concrete recovery plan after failure.",
  "evidence": [
    {
      "source": "simulation_turn",
      "sourceId": "turn_04",
      "quote": "I spoke with the team, changed the timeline and assigned owners."
    }
  ]
}
```

Модель способна выдать красивый балл с несуществующей цитатой, а это убивает главный принцип. Поэтому **после каждого ответа модели код проверяет каждую цитату**:

1. Цитата ищется в указанном источнике (`sourceId`) дословно — с точностью до пробелов и регистра кавычек.
2. Цитата не найдена — это доказательство выбрасывается, а событие пишется в лог.
3. У балла не осталось ни одного валидного доказательства — балл становится `null`.
4. Если выброшено больше половины доказательств ответа, запрос считается неудачным: один повтор, затем понятная ошибка.

## 4. Модули и API

Все публичные запросы идут с заголовком `X-API-Key`. Каждый создающий `POST` принимает `Idempotency-Key`: повтор с тем же ключом возвращает уже созданный ресурс, а не второй.

| Модуль | Глубина | Эндпоинты | Выход |
|---|---|---|---|
| **M1 Brief** | тонко | `GET /v1/candidates/:id/brief` · `GET /v1/briefs/:briefId` | вопросы по D.R.I.V.E., о знании inVision U, об английском и о мотивации; сверка данных до интервью; evidence на каждую рекомендацию |
| **M2 Simulator** | **полностью** | `POST /v1/simulations` · `POST /v1/simulations/:id/turns` · `POST /v1/simulations/:id/complete` · `GET /v1/simulations/:id` | сценарий назначается случайно из 10; ход — голосом, расшифровка, реплика персонажа ≤ 60 слов голосом и субтитрами; по завершении — полный транскрипт с id ходов |
| **M3 Judge** | **полностью** | `POST /v1/simulation-assessments` · `GET /v1/simulation-assessments/:id` · `GET /v1/simulation-assessments/:id/candidate-feedback` | комиссии: баллы `0–4 \| null` с `turnId`, уверенность, English metrics отдельно, вопросы для живого интервью. Кандидату: развивающий отзыв без баллов, ранжирования и намёков на решение |
| **M4 Draft** | тонко, но запрет настоящий | `POST /v1/interviews` · `POST /v1/interviews/:id/recording` · `POST /v1/interviews/:id/interviewer-scores` · `POST /v1/interviews/:id/assessment-draft` · `GET /v1/interviews/:id/assessment-draft` | расшифровка интервью (из записи inVision или записанная на экране интервьюера), черновик с цитатами из реплик кандидата, совпадения и расхождения с оценкой интервьюера |
| **C Сверка данных** | тонко, но на всех этапах | `GET /v1/candidates/:id/consistency?stage=before\|after` | заявленное против измеренного (английский, знание inVision U, мотивация, опыт) до и после интервью; статус и что делать; только сигналы, решение за людьми |
| **S Сюрпризный вопрос** | после пула сценариев, первым отрезается при нехватке времени | `POST /v1/surprise-questions` · `…/start` · `…/answer` · `GET …/:id` · `GET …/:id/video` | вопрос по анкете, одна попытка, видео для сотрудников, расшифровка и цитаты в брифе |
| **M5 Calibration & Question Quality Guard** | демонстрация на seed-истории | `POST /v1/quality-checks/interview` · `POST /v1/quality-checks/calibration` · `GET /v1/quality-checks/:id` | наводящие и некорректные вопросы, неравное покрытие D.R.I.V.E., сдвиг шкалы интервьюера, рекомендации |

**Серверное правило M4:** пока интервьюер не сохранил свои баллы, черновик нельзя ни сгенерировать, ни получить — оба запроса отвечают `409`. Это дешёво и держит главный принцип, поэтому делается всерьёз, даже при тонком M4.

**Расшифровка интервью.** ИИ читает само интервью, а не пересказ интервьюера:
- **Два источника.** inVision присылает расшифровку своей записи, или интервьюер записывает звук на своём экране — только с отмеченным согласием кандидата.
- **Как расшифровывается.** Запись расшифровывается через шлюз (Deepgram, разделение по говорящим).
- **Что остаётся.** Аудио удаляется сразу после расшифровки. В модель уходит только текст, в репозиторий записи не попадают.
- **Зачем.** Черновик M4 цитирует реплики кандидата с таймкодом. M5 проверяет реальные вопросы интервьюера и долю его речи.

**Почему M5 так назван.** На трёх синтетических кандидатах честно доказать реальную предвзятость нельзя. M5 показывает сигналы качества вопросов и калибровки с рекомендациями — и не называет это «обнаружением дискриминации». Выводов о личности кандидата он не делает и его оценку не меняет.

inVision присылает снимок кандидата в теле запроса, поэтому синхронизировать базу заранее не нужно. Любой результат доступен и как JSON-файл той же схемы.

## 5. Симулятор — главный продукт

**Голосом, десять разных сюжетов, у каждого свой.** Кандидат говорит, а не печатает: вставить заготовленный ответ нельзя. Сценарий назначается случайно, поэтому ответы нельзя подсмотреть у знакомых.

```
голос кандидата ─▶ Deepgram: речь → текст ─▶ мини-ML: на какой тип ответа похоже ─▶ ветка сценария
                                                                                     │
      голос персонажа ◀─ Deepgram Aura ◀─ OpenAI: живая реплика персонажа для этой ветки ◀┘
```

- **Десять сюжетов** в `config/scenarios/<id>.json`: конфликт в команде, нехватка ресурсов, этическая дилемма, провал проекта и ещё шесть. Сюжеты полностью разные, но построены по одной схеме:
  - 5–7 битов, 6–10 ходов кандидата, 6–8 минут;
  - бит описывает цель, какие компетенции D.R.I.V.E. он даёт проявить, **3–5 типов ответа** с примерами фраз и веткой для каждого, запасную ветку и лимит ходов;
  - **каждый сюжет даёт проявить все пять компетенций** — иначе баллы из разных сценариев нельзя сравнивать.
- **Назначение:** случайно среди сценариев со статусом `ready`, сначала наименее использованные; одна симуляция на кандидата. Сценарий получает `ready`, только когда прошёл стенд качества: три эталонных прохождения (слабое, среднее, сильное), судья ставит баллы в пределах ±1 от ожидаемых, все цитаты дословные.
- **Мини-ML** — локальная модель эмбеддингов в ML-сервисе, $0. Она сравнивает расшифрованный ответ с примерами фраз каждого типа ответа в текущем бите и выбирает ветку. Если сходство ниже порога, выбирается запасная ветка. Каждое решение — тип ответа, сходство, ветка — пишется в журнал: это объяснимость.
- **Мини-ML ведёт сюжет, но не ставит баллы.** Баллы ставит только судья M3 по всему транскрипту с цитатами. Любая ветка даёт проявить все компетенции, поэтому выбор ветки не наказывает.
- **Актёр** (OpenAI) пишет реплику персонажа для выбранной ветки — ≤ 60 слов, в образе. **Библия персонажа:** характер, цели, скрытый мотив, эмоциональное состояние (спокоен → защищается → сотрудничает).
- **Ограничения:** персонаж не оценивает, не подсказывает «правильный» ответ, не спрашивает о личном и о тяжёлом опыте. Уход от темы — мягкий возврат. Кандидат может остановиться в любой момент.
- **Голос:** «нажал — сказал — отпустил», до 60 секунд на ход. Субтитры всегда видны: кандидат видит, что распознано, и может перезаписать ход до отправки. Цель задержки ответа — меньше 3 секунд.
- **Текстовый режим — только по заявке.** Сотрудник включает его для конкретного кандидата (нет микрофона, нарушение речи). Вставка текста заблокирована и там, а в отчёте видно, что симуляция шла текстом.
- **Справедливость к английскому:** судья читает смысл; акцент и темп на баллы не влияют. Низкая уверенность распознавания — флаг для человека, а не штраф.
- **Запись сессии:** транскрипт, биты, решения мини-ML и режиссёра; комиссия переходит от цитаты прямо к ходу.

**English metrics считаются кодом, $0:** слова в минуту по таймкодам речи, доля слов-паразитов, средняя длина реплики, лексическое разнообразие, ошибки через LanguageTool (локально), оценка CEFR. Голосовой ввод делает все метрики доступными; именно их сверка сравнивает с заявленным уровнем.

## 6. Seed-кандидаты

| Кандидат | Цель демо |
|---|---|
| **A** | сильное execution, но недостаточно evidence по values |
| **B** | сильная vision, сложность с resilience |
| **C** | противоречивые ответы и явный `insufficient evidence` |

Для каждого кандидата готовим:
- обезличенную анкету и ответы теста;
- ожидаемый M1-бриф;
- транскрипт симуляции и ожидаемый M3-отчёт;
- заметки интервью, баллы интервьюера и сценарий M4;
- историю вопросов и оценок для M5;
- записанные ответы моделей для replay и `DEMO_MODE`.

## 7. Структура репозитория

```
apps/web/                 Next.js; кандидату — English, сотрудникам — EN/RU (Мейірбек)
apps/api/src/
  modules/{briefs,simulations,simulation-assessments,interviews,quality-guard,candidates,audit}/
  ai-client/  privacy/to-llm-view.service.ts  auth/  config/            (Айбек)
services/ml/app/
  gateway/  providers/  schemas/  cache/  evidence/  metrics/english.py
  modules/{m1_brief,m2_simulator,m3_judge,m4_interview_draft,m5_quality_guard}.py   (Наурызбек)
config/
  rubric.drive.json  models.json  scenarios/*.json
  prompts/{m1-brief,m2-director,m2-actor,m3-judge,m4-interview-draft,m5-quality-guard}.md

fixtures/cassettes/       записанные ответы моделей и Deepgram

```

`models.json` задаёт для каждой задачи провайдера, запасную модель, `max_tokens`, лимит стоимости на запрос, TTL кэша и запрет вызова в `DEMO_MODE`, если есть seed-результат. `services/ml/app/evidence/` — проверка дословности цитат.

**Переносим из черновика:** дизайн-систему (`apps/web/app/style.css`, `components/ui/*`, две темы, шрифты), каркас Next.js, MSW, генерацию клиента, экраны стенда (вход, анкета, тест на моках), каркас NestJS и Prisma, FastAPI-заготовку `services/ml`, английские тексты из `apps/web/messages/en.json`.

**Не переносим:** смену языка, старые слайсы S0–S10, контракт старого продукта в роли основного API.

## 11. Правила работы

- В `main` — только через PR; прямой пуш и force-push запрещены настройкой GitHub всем, включая владельца. Одобрить PR может только Мейірбек — он единственный в `.github/CODEOWNERS`. Свои PR он мерджит сам после зелёного CI.
- Одна ветка — один слайс одного человека. Маленькие коммиты с понятными сообщениями.
- Контракт слайса мерджится первым; фронтенд работает на MSW-моках из него.
- Код, идентификаторы, комментарии и интерфейс — на английском.

**Бюджет:**
- по умолчанию у всех `GATEWAY_MODE=replay`;
- живые вызовы — только по отдельным ключам проекта OpenAI с лимитом на каждый ключ: у Мейірбека и у Наурызбека (ему нужны живые вызовы, чтобы писать промпты); Айбек работает на replay;
- лимит стоимости на один запрос в `models.json` и общий жёсткий `BUDGET_USD_CAP` в шлюзе.

**Публичный репозиторий:**
- ключи только в `.env`, в репозитории — `.env.example` без значений;
- включены GitHub secret scanning и push protection: пуш с ключом отклоняется ещё на сервере;
- в CI — отдельная проверка секретов;
- в репозиторий попадают только синтетические данные; записи голоса кандидатов — никогда.

## 14. Definition of Done

Проект готов к питчу, когда:

- [ ] Минимальный путь питча проходит для A, B и C с `DEMO_MODE=true` и выключенной сетью (`GATEWAY_MODE=replay`) за пять минут.
- [ ] M2 проходится голосом от начала до конца; текст — только при включённой доступности, вставка заблокирована.
- [ ] Сценарий назначается случайно среди `ready`; все сценарии `ready` прошли стенд качества.
- [ ] Сверка показывает «заявлено против измерено» до интервью и итог после.
- [ ] Каждый AI-вывод имеет доказательство с цитатой, прошедшей проверку дословности, — или `null`; тест подсовывает выдуманную цитату и получает `null`.
- [ ] Все AI-ответы проходят проверку схемы.
- [ ] PII-тест подтверждает, что запрещённые поля не уходят в ML, а ML отклоняет запрос с таким полем.
- [ ] Английский не меняет баллы D.R.I.V.E. (тест: один транскрипт с ошибками и без — одинаковые баллы).
- [ ] M4 серверно заблокирован до оценок интервьюера — и генерация, и чтение (тест на `409`).
- [ ] Запрос без `X-API-Key` отклоняется; повтор с тем же `Idempotency-Key` не создаёт дубль.
- [ ] Кандидат не видит баллы и намёки на решение.
- [ ] CI зелёный, включая проверку секретов.
- [ ] Лог стоимости укладывается в $20.
